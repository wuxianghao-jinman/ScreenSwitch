# 屏幕开关 · 1.3

一个原生 macOS 菜单栏工具：保持 MacBook 上盖打开，关闭内建屏，仅使用外接屏。由 Codex 辅助开发。

授权范围：允许个人使用、员工日常办公使用、学习修改及免费分享；禁止利用软件或相关服务获利。完整条款见 [LICENSE](LICENSE)。

2026-09-30，在 Apple M5 MacBook Pro、macOS 26.0、P275MV PLUS 外接屏的现场测试中，用户观察确认：稳定期间只有外接屏亮着，内建屏保持黑屏，外接屏继续作为主屏使用。该结果仅代表已验证的设备与系统组合。

从本仓库的 Releases 下载 `ScreenSwitch-1.3.zip`，解压后保留应用与恢复脚本在同一目录。GitHub 自动生成的 Source code 压缩包是源码，需要自行构建。

## 使用

1. 双击「屏幕开关.app」。它会在顶部菜单栏显示笔记本图标，不打开主窗口。
2. 连接并唤醒外接屏，使用扩展显示模式，保持电脑上盖打开。
3. 点击菜单栏图标，选择「关闭本机屏幕」。所有屏幕会先淡出到黑色，外接屏重新同步后再淡入；稳定后外接屏继续显示，内建屏从活动桌面中移除。
4. 点击「恢复本机屏幕」或按 **⌃⌥⌘R**（Control+Option+Command+R）恢复两屏。退出时选择「恢复并退出」。

没有可用外接屏时，关闭按钮不可用。若检测到上次遗留的恢复快照，请先点「恢复本机屏幕」。

以下情况关闭按钮也不可用，菜单中会显示原因：

- **BetterDisplay 或 Lunar 正在运行**：它们也会修改显示配置，请先退出。
- **macOS 版本变了**：本工具只在 macOS 26.0（25A8353）上做过现场验证。系统更新后，先点「安全测试（关闭 5 秒后自动恢复）」，确认内建屏黑屏、外接屏正常、之后两屏恢复，再选「正常」，即可在该版本启用。选「不正常」请停止使用。

可将整个「屏幕开关」文件夹移动到方便的位置；保留随附恢复脚本与应用在同一目录。

## 布局与恢复

关闭前保存显示器身份和位置，使用系统保存的显示器配置执行断开。恢复时，如果仍连接同一组屏幕，会恢复原来的主屏和位置；屏幕组合改变时，让 macOS 自动安排可用屏幕。恢复时启用内建屏并同时固定外接主屏位置，通常一次切换即恢复原布局；位置仍不一致时再补一次调整。

- 正常退出前恢复；恢复失败会保留程序以便重试。
- 独立恢复进程在主程序崩溃或被强制结束时尝试恢复，失败时约 1 分钟内持续重试。
- 登录恢复：首次关闭屏幕时会在 `~/Library/LaunchAgents/local.wuxianghao.ScreenSwitch.login-restore.plist` 写入一个登录项。每次登录时它检查是否有未恢复的快照，有则恢复内建屏，没有则立即退出。它覆盖重启、注销或两个进程同时被终止的情况。系统可能提示「已添加后台项目」。
- 恢复后核对屏幕位置，不一致时最多重试 3 次；仍不一致时内建屏保持开启，菜单提示到系统设置中调整。
- 拔掉最后一个可用外接屏时尝试恢复内建屏。
- 睡眠前尝试恢复；唤醒后如需关闭，请再次点击。

两个进程同时被终止时，会在下次登录时由登录恢复项恢复。系统故障或显示接口失效时，自动恢复可能无法完成；恢复快照会留在本地，供随附恢复脚本使用。

## 手动恢复

先按 ⌃⌥⌘R（应用运行时有效）。或在外接屏上双击「恢复本机屏幕.command」。它会调用同目录应用恢复内建屏与保存的布局。也可以尝试合上再打开电脑上盖；仍无法恢复时，注销后重新登录或重启。

命令行读取状态：

```bash
./屏幕开关.app/Contents/MacOS/ScreenSwitch --status
```

## 兼容性与本地数据

- 构建目标为 Apple 芯片 Mac、macOS 14 或以上；仅在上述 M5 / macOS 26.0 配置完成现场验证。
- 使用 SkyLight 未公开接口，后续 macOS 更新可能改变其行为。
- 切换和恢复时，外接屏可能短暂黑屏并重新同步。
- 使用本地临时签名，未取得 Apple Developer ID 签名或公证。
- 应用本身不自动开机启动，不联网。登录恢复项只在有未恢复快照时工作。仅在应用偏好设置中保存用于恢复的显示器编号、UUID、位置和已验证的系统版本号；恢复成功后删除快照。
- 移动应用后，下次关闭屏幕时会自动更新登录项中的路径。不再使用本工具时，删除上述 plist 文件即可移除登录项。
- 避免同时使用其他显示器开关工具，以免配置互相覆盖；BetterDisplay、Lunar 运行时会阻止关闭。
- 镜像模式、真实拔插和睡眠唤醒尚未完成现场验证。

## 源码与参考

源码位于「源码」目录，无第三方包依赖。需要 Apple 芯片 Mac、macOS 14 或以上，以及 Xcode Command Line Tools 提供的 Swift 编译器。

在仓库根目录运行：

```bash
bash 源码/test.sh
bash 源码/build.sh
```

测试使用模拟显示后端，不会关闭实际屏幕。构建完成后，仓库根目录会生成「屏幕开关.app」，并自动设置恢复脚本的执行权限。双击该应用即可启动，根目录的恢复脚本可以直接配套使用。应用与构建缓存不纳入源码版本管理。

目录结构：

```text
ScreenSwitch/
├── README.md
├── LICENSE
├── 验证记录.md
├── .gitignore
├── 恢复本机屏幕.command
└── 源码/
    ├── DisplayCore.swift
    ├── NativeLayout.swift
    ├── main.swift
    ├── Tests.swift
    ├── build.sh
    └── test.sh
```

实现查阅了 [Apple Quartz Display Services](https://developer.apple.com/documentation/coregraphics/quartz-display-services)、本机 CoreGraphics / Foundation SDK 头文件，以及 [displaytoggle 的 SkyLight 接口声明](https://github.com/calvincchan/displaytoggle/blob/main/Sources/displaytoggle/SkyLightBridge.h)。同时参考 [BetterDisplay 官方文档和发行包](https://github.com/waydabber/BetterDisplay)，核对了其显示器配置提交方式。

本工具的源码独立实现。BetterDisplay 的核心实现未公开；静态观察到的调用差异不能代表其全部实现。具体验证结果见[验证记录](验证记录.md)。
